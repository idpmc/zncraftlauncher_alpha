# 合规整改清单：原版游戏本体下载功能隔离

> 起因：2026-10-20 PCL 发布 2.99.0.0，release note 为「为遵守相关法律法规，PCL 不再提供 MC 下载功能」，
> 并注明「与网易微软麻将无关」。同日 HMCL 亦准备在国内发行版关闭原版下载。
> 本项目采取方案 C：**双构建开关**，国内发行版不提供下载入口。

## ⚠️ 当前阶段：A 阶段（运行时禁用），**未**达到"物理剔除"

**本阶段产物仍然包含下载相关代码。** 这一点必须如实描述，不得对外宣称"反编译找不到下载逻辑"。

实测（`npm run build` 后检索 `out/main/index.js`）：

| 字符串 | 结果 |
|---|---|
| `bmclapi` | PRESENT |
| `launchermeta.mojang.com` | PRESENT |
| `piston-meta` | PRESENT |
| `libraries.minecraft` | PRESENT |
| `installBaseVersion`（函数名） | ABSENT（仅函数名被压缩，函数体仍在） |

原因：下载函数定义在 `src/main/index.ts` 内部（`installBaseVersion` 等），
esbuild 不做跨函数活跃性分析。调用点包 `if (__ENABLE_MC_DOWNLOAD__)` 只让代码**不被执行**，
不会让代码**不出现在产物里**。URL 字面量无人引用也照样保留。

**因此 A 阶段的准确定性是：**

- ✅ 国内版：界面无下载入口、不会执行任何本体下载网络请求
- ❌ 国内版：产物中仍可搜到镜像/官方源地址，反编译可还原下载逻辑
- ⚠️ 该状态下**不要**投放到国内公开分发渠道并宣称合规；仅适合内部使用/小范围

### B 阶段（待办）：构建期物理剔除

要真正"反编译找不到"，唯一办法是**把下载函数从 `index.ts` 物理搬到独立文件并用动态 `import()` 引用**：

```
src/main/download/
  index.ts        // 统一导出
  vanilla.ts      // 原版 JSON / jar / assets
  libraries.ts    // 库补齐
  loader.ts       // Fabric / Forge / NeoForge
```

调用点写法必须保证 `false` 分支内无静态引用：

```ts
if (__ENABLE_MC_DOWNLOAD__) {
  const dl = await import('./download')   // 关闭时整个模块图不进产物
  await dl.ensureBaseGameFiles(...)
}
```

循环依赖用 `DownloadDeps` 接口注入（`getMinecraftDir` / `mt` / `httpFetch` / `orderByDownloadSource`
等由主进程在启动时传入），不要靠先包守卫规避。

预计工作量：约 1200 行搬迁 + 依赖注入改造，半天到一天。

## 五、明确保留（不属于分发红线）

- **Java 运行时下载**（Mojang 分发物，服务对象是本地游戏）
- **Modrinth 第三方资源**（mod / 光影 / 资源包，平台明确允许再分发）
- **本地识别、导入、解压、校验、启动、日志分析、模组管理、JVM 调优**
- **本地服务器**：仅保留启动已存在的 `server.jar`
- **跳转官方渠道**：用内置浏览器打开 `https://www.minecraft.net/zh-hans/download`，
  文件由 Mojang 直接分发给用户，启动器不经手任何字节

### 跳转官方渠道的红线

- ✅ 只跳**官方**页面（minecraft.net / Mojang），不跳镜像或第三方下载站
- ✅ 只做被动展示，**不**自动填表单、**不**自动点击下载、**不**抓取下载链接
- ❌ 一旦加入任何自动化操作，就重新变成"帮用户下载"
